# 検証と保存

## 現在の候補を検証する入力

事前検証は選択プロファイルの解決済み値、評価設定、ルートエージェントから参照する指示・子エージェント、モデル・SDK・推論条件、診断入力と、ソース・テスト・品質スクリプト・ビルド・依存定義を照合します。サブパッケージも再帰走査し、インストール済みコードの欠落・変更・余分なファイルを拒否します。

提出時刻、手動分類、未選択プロファイルは候補の挙動に関係せず、検証を失効させません。選択済み評価設定や品質保証コードの変更は失効させます。診断成果物・JUnit・ZIPの改変や欠損も拒否します。

## 環境の準備と実行条件

環境準備の証拠はPython、依存入力とロック、Wheel、スナップショットに結び付けます。推論・表示・提出条件だけの変更は環境再作成の理由にしません。ホスト端末の色指定（NO_COLOR、FORCE_COLOR、CLICOLOR、CLICOLOR_FORCE）は課題テストから除外します。ローカルCPUと公式SDKの開発用サンドボックスで同じ方針を使い、課題が明示した表示条件を確認します。

診断とSDK確認の実行記録には、その時点の解決済み設定とコードの証拠を別途保存します。

未修正と参照修正でテストが識別できること、テストと同じプロセスが対象ソースを読むことが比較課題の条件です。固定済み選定の再検証は同じ課題・順序を使い、失敗しても補欠を選びません。新しい記録を作り、過去の評価を修正しません。

過去の選定は記録・ケース・JUnitのハッシュと判定の整合性を確認して読みます。現在の候補の事前検証には、これに加えて現在の設定・コードとの一致が必要です。過去の検証と現在の検証を混同しません。

## ZIPの再現性

候補と実行バンドルのZIPは同じ保存処理を使い、エントリ順・時刻・圧縮方式を固定します。同じ内容から同じバイト列を生成し、ファイルの更新時刻へ依存しません。過去のZIPは再包装せず、当時のハッシュで検証します。新しい正規化ZIPと過去のZIPは内容IDで対応づけ、過去のハッシュを書き換えません。

## 結果と公開範囲

公式SDKの課題単位判定を正本とし、未評価を失敗へ、欠損を成功へ置き換えません。課題ID、件数、集計、保存ファイルの一致を検証します。実行順序は配列で保存し、辞書のキー順から復元しません。

公開台帳はID、分類、構造指標、必要なハッシュと集計値だけを含みます。課題文、正解・生成パッチ、ZIP、実行ログ、認証情報はGitやActions成果物へ保存しません。履歴を結合する場合は明示指定した入力のハッシュも固定し、欠損・改変・集計不一致を失敗にします。

## 品質ゲート

`make check`は開発用パッケージを更新して`make verify`を実行します。formatter、lint、型、依存・循環検査、全テスト、行90%以上・分岐80%以上を必須とします。固定版提出SDKの合成HTTP契約テストは外部へ送信しません。準備済みCPUでの実データ診断とSDK確認は通常CIから分けます。

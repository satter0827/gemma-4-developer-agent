# コーディング規約

## 設定と定数

動作を調整する数値は設定から読み、型・範囲・単位を検証します。Kaggle実行条件は実行設定、パッチの条件は診断設定、候補の入力と保存先は事前検証設定に置きます。ローカル表示と品質の設定はpyproject.tomlへ置きます。欠落をコードの初期値で補いません。

仕様で固定されるポート上限や百分率の基数は、責務を持つモジュールで名前付き定数にします。JSONの字下げ、単純な添字、0・1・−1は文脈で意味が明白な場合に直接記述できます。ただしタイムアウトや再試行上限が1でも、調整値なら設定が必要です。ケース数はケース定義から求め、別の設定へ複製しません。

数値比較はlint、運用引数と既定値の直書きは構造テストで検査します。文字列に含まれる数値、数値の意味、設定の重複までは機械判定しません。レビューでは、定数化で可変値を隠していないか、単位が名前から分かるか、既存設定を再利用できるかを確認します。無名の定数名、計算式による回避、ファイル全体の規則除外は禁止します。例外は該当箇所で理由を説明し、検査を最小範囲に限定します。テストの期待値は設定化しません。

## 依存と副作用

依存の許可方向とモジュール分類はpyproject.tomlで管理します。循環依存は関数内や型検査専用のimportも禁止します。実行コードからテストや開発用入口へ依存させません。新規モジュールは必ず一つの担当へ分類し、削除したモジュールの分類も残しません。分類の重複と許可先の未定義は構造検査で拒否します。importだけで通信、ファイル変更、外部プロセス起動、モデル初期化を行いません。

CLIは入力と表示、実行処理は手順、公式接続は外部APIとの境界を担当します。汎用バックエンド、プラグイン、互換ラッパーを必要なしに追加しません。

## 検証と結果

保存と後始末を独立させ、保存失敗時も子プロセスやモデルを停止します。元の失敗を後始末の失敗で消しません。テスト0件、成果物の欠落・重複・変更は成功にしません。診断結果、エージェント評価、正式な採点は分けて記録します。

formatter・lint・型チェック・関連テスト・行と分岐のカバレッジを確認します。基準を緩めて通過させません。利用者向け説明は日本語、コード・ログ・エージェント指示は英語で統一します。競技データ、正解・診断パッチ、LoRA、ログ、認証情報はGitやCIへ含めません。

## 比較と実行予算

比較条件は実行前に固定し、変更する因子を一つに絞ります。モデルの結果を見てから課題を除外・追加しません。生成予算、採点時間、Notebook全体の期限、GPUのquota時間は別の単位として設定と記録を持ちます。見積もりを実測値として扱いません。

テストは同じ一時保存先で並行実行しません。全体検証中は実行対象のコードを固定し、修正後に開発用パッケージを更新して再検証します。外部SDKの本物の接続確認は専用の準備済みCPU環境で行い、通常CIの合成テストの成功と区別します。

正式評価の環境、欠けたトレース、スコアの分母など、確認していない情報を既知の値や失敗なしへ置き換えません。開発用の環境補正は記録し、正式採点との完全一致と説明しません。

実行順序は配列として保存します。JSONのキーソートや集合から順序を復元しません。対応表の辞書と実行順序を分け、複数件・辞書順と逆の並びでも同じ順序が保持されることを検証します。

# 競技と採点

確認日：2026年10月21日。公式の評価説明、データ説明、競技ルール、日程を再確認しています。日程と運用条件は主催者が更新する可能性があります。

## 解決した課題の割合を競う

公式評価は課題ごとの合否です。生成した修正を対象リポジトリへ適用し、検証テストが通った課題の割合をスコアとします。説明の説得力、修正行数、途中で通った個別テストの割合に独立した加点があるとは説明されていません。部分的な改善でも必要な検証を満たさなければ、その課題の解決にはなりません。[公式評価](https://www.kaggle.com/competitions/gemma-4-developer-agent/overview/evaluation)

この採点では、一部の課題を確実に解く方針に意味があります。ただし、公開課題の難度と非公開課題の解決しやすさが一致するとは限りません。探索、編集、検証のどこで失敗したかを分け、解けたはずの課題を取りこぼす原因を調べる必要があります。

## 開発課題と本番課題

公開データには129問の課題文、ソースのスナップショット、参照修正、検証テストがあります。正式評価では別の非公開課題へ置き換えられます。公式データ説明は非公開課題を約120問、PublicとPrivateを同程度に分割すると説明しています。これは最終的な正確な分母の保証ではありません。Publicのスコアから、解けた問題IDやPrivateの成績は分かりません。[公式データ](https://www.kaggle.com/competitions/gemma-4-developer-agent/data)

公開スコア0.01だけから「1問解決」「個別テストの1%通過」とは確定できません。正確な課題数、表示の丸め、課題別結果を確認できていないためです。開発用の2問で0件だった結果とも矛盾しません。

## 提出物と実行制約

提出物はルートにエージェント定義を持つZIPです。公式の宣言形式からエージェントをコンパイルし、共通のGemmaモデルを主・補助エージェントで使います。対応する量子化済みモデルは31B、12B、E4B、E2Bで、LoRAの同梱が認められています。モデル混在、提出物の外を指す参照やリンクは許可されていません。[モデル・ツール・実行規則](https://www.kaggle.com/competitions/gemma-4-developer-agent/overview)

公式の生成予算は全課題合計12時間で、環境準備を含み、生成後のパッチ検証時間を含みません。課題ごとの生成上限は提出設定で指定できます。開発用の採点待ち時間、Notebook全体の期限、GPUのquotaはそれぞれ別の制約です。[公式評価](https://www.kaggle.com/competitions/gemma-4-developer-agent/overview/evaluation)

本番のPython、sandbox manager、依存Wheelの全ハッシュは未確認です。公開SDKの開発環境で成功したことを、本番環境と完全に一致した証拠にはしません。

# 実行ログ

ログは処理の経過を調べるために使います。公式判定、候補の同一性、受付状態は、それぞれの確定記録を照合します。ログの有無から成功を決めません。

## 形式と文脈

標準ライブラリのloggingとjsonで、UTF-8のJSON Linesを出力します。1行が1イベントです。時刻はUTCのISO 8601、共通項目はレベル、logger、イベント名、メッセージ、プロセスID、実行IDです。実験、セッション、課題、候補、段階が分かる場合は同じ行に加えます。未確認の時間や結果はnullにします。

CLIは`artifacts/logs/<execution_id>/`、診断・評価・最適化は実行ディレクトリ内の`logs/events/`へ保存します。プロセスごとにファイルを分け、子プロセスへ実行IDを渡します。文脈はcontextvarsで管理し、処理が終わると元に戻します。import時にはファイルを作りません。

既定はファイルINFO、コンソールWARNING以上です。コンソールは標準エラーに限定し、コマンドの結果やJSONを出す標準出力へ混ぜません。10 MiBでローテーションし、3世代を残します。設定はpyproject.tomlに置き、Notebookには解決済みの値を渡します。

## 記録する境界

準備、依存導入、候補固定、モデル起動・停止、課題評価、Skill検証、最適化、同期、提出判断の開始と終了を記録します。課題の未解決と改善なしはINFO、継続可能な証拠不足はWARNING、処理失敗はERRORです。詳細な照合はDEBUGで扱います。

ツールの観測は保存トレースから名前、担当、結果、引数検証エラーを抽出します。ツール固有の所要時間が確認できない場合はnullです。呼出しを編集成功とみなさず、実装差分と公式判定を別に扱います。複数の呼出しに一つの応答が対応する場合は、個々の成否を割り当てません。

課題本文、パッチ、モデルの入出力、ツール引数全文、環境変数、認証情報は複製しません。許可した項目と型だけを渡し、例外は型とファイル名・行・関数名に絞ります。例外本文、ソース行、ローカル変数は出力しません。

## 保存と後始末

イベントは追記用です。SDKの課題ログ、トレース、テスト出力、vLLMログは従来の形式を保持します。イベントログは確定済み採点証拠のハッシュへ含めず、Git、MLflow、Actions成果物、提出ZIPへ保存しません。

初期化できない場合は標準エラーへ知らせて停止します。実行途中の保存不能は一度だけ知らせ、採点結果・受付状態の保存と後始末を続けます。元の例外があれば保持し、なければ処理終了時にログ保存失敗を返します。ログ障害を未解決に置き換えず、評価や提出を再実行しません。

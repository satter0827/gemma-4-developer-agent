# Easy課題の実験準備とCPU検証（2026年10月21日）

実験IDは`easy-sequential-v1`、検証記録IDは`easy-sequential-cpu-v1`です。調整用36問と確認用12問を固定し、調整用の6問で対照検証を行いました。モデルを使った解決率は未評価です。

## 条件

モデルはGemma 4 31B QAT、LoRAは既存の検証済みZIPから同じバイト列を使用します。生成条件は温度0.2、top-p 0.95、出力上限16,384トークン、thinking budget 4,096、seed 0です。生成5分・30ツール呼出し・50ターンを各課題で共有し、公式パッチ検証の上限は300秒です。

比較対象は既存の手順付きエージェントと、修正担当・検証担当を順に実行する構成です。両者でモデル、LoRA、サンプリング、課題と評価条件を固定します。予定順序は課題ごとにAB/BAを交互にします。GPUセッションは90分、後始末用は5分、各評価の追加時間見積もりは1分で、新しい組の開始には27分以上の残時間が必要です。

公式SDKはswegemma 0.2.11、adk-submission 0.2.13、adk-eval-core 0.1.0、Google ADK 1.36.1です。SDKのCPU環境、課題テストのCPU環境、MLflowのCPU環境を分離しています。

## エージェントと実験管理の検証

同じバンドルから候補2件を公式SDKでコンパイルしました。合成応答では修正→検証の順序、短い引き継ぎ、検証担当への古い履歴の遮断、失敗後の再試験、最後の提出ツール、共有ツール上限を確認しました。修正担当2回・検証担当4回のモデル応答を合成し、消費するツール呼出しは合計3回でした。モデル推論とKaggleへの正式提出は行っていません。

CPU証拠は課題専用環境の対照検証と、公式SDK環境でのコンパイル・合成応答を結合しています。Kaggleの開発用実行では、公式ハーネスの対照検証をモデル起動前に改めて行います。正式採点環境との一致や精度改善を示す結果ではありません。

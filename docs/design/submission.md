# 提出の状態管理

候補の検証証拠は`candidates.evidence`、提出状態は`submission.state`が管理します。検証済みZIPの登録と、時刻・残枠・重複・受付不明の判断を分離します。

## 提出判断

登録順で未受付の候補を選び、公式残枠、UTC日付の上限、手動提出から24時間、送信時刻、全体期限を照合します。受付済みの採点待ちは別候補を妨げません。受付不明の試行があれば送信を停止します。

正式受付前に試行をGit状態ブランチへ確定します。更新元コミットを照合し、競合・保存失敗時は送信しません。アップロード後に履歴と残枠を再取得し、正式受付API直前にも時計を確認します。08:55以降は開始しません。

## 状態遷移

| 状態 | 遷移条件 |
|---|---|
| 未試行 | 条件が揃えば試行を保存する |
| 受付不明 | 正式APIの応答不明、受付ID欠落、期限超過。自動再送しない |
| 受付済み | 応答ID、または後続同期で試行識別子と内容を照合できた |
| 未受付確認済み | 履歴と画面を確認した明示解除。候補は再び判断対象になる |

履歴のZIP内容も照合し、手動で送った候補を二重送信しません。公開スコア確定済みから上位2件を整理し、同点は新しい提出を優先します。最終選択チェックは未確認と表示します。

## 通知と停止

通常終了・候補なし・保留・採点更新は実行要約へ残します。既知の異常は初回だけ失敗通知の対象とし、回復するまで状態を保持します。未処理例外や状態保存失敗は通常の失敗です。

締切後は送信せず夜の確認だけを行い、最終確認後に定期実行を停止します。遅延した実行でも期限を再判定します。認証情報と書き込み権限は提出用ワークフローに限定します。

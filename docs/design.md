# 設計

## 責務

| 担当 | 主なモジュール | 役割 |
|---|---|---|
| 設定 | `config`、`task_catalog`、`diagnostic_config` | 型、範囲、必須値、パス、課題と依存関係を検証 |
| CPU診断 | `diagnostics`、`qualification`、`runtime_checks` | 準備と実行、原因再現、モデル実行前の課題選定 |
| 公式接続 | `official`、`official_cpu`、`sandbox_sources`、`environment` | 公式API、合成入力でのSDK確認、開発用環境補正、Wheel照合 |
| 候補の固定 | `preflight`、`candidates`、`packaging` | 既存診断・品質・参照・ZIPの照合と記録 |
| バンドル生成 | `kaggle_bundle`、`diagnostic_bundle` | 必要な実行コードと入力だけをPrivate Notebookへ渡す |
| Kaggle実行 | `runtime`、`diagnostic_kaggle`、`worker` | 実行順序、参照検証、推論、保存、期限と終了 |
| 結果 | `results`、`analysis`、`test_evidence`、`provenance`、`artifacts` | 公式結果、JUnit、読み込み元、派生分析、ハッシュを照合 |
| 操作・品質 | `cli`、`processes`、`gpu_budget`、`scripts/` | 入力と表示、プロセス停止、予算の判定、品質ゲート |

依存の許可方向とモジュール分類は`pyproject.toml`が管理します。循環参照、担当違反、未分類、ローカル経路からの推論ライブラリ参照、import時の実行を構造テストで検査します。公式SDKの確認は別プロセス・別CPU環境へ隔離します。汎用バックエンドやプラグイン登録機構は持ちません。

## 入力と設定

共通課題定義は課題データ、スナップショット、公式テスト対象、ソースルート、import対象、追加依存Wheelのハッシュを持ちます。生成パッチと原因確認用差分は診断設定が持ち、比較課題の定義には要求しません。

実行プロファイルは用途、評価設定、主エージェントの指示、固定済み課題の記録を指定します。CLIのプロファイルは必須です。欠落した値をコードの初期値で補いません。比較候補では、同じモデル・アダプター・補助エージェント・ツール・生成設定を使い、主指示だけを差し替えます。

調整値は設定へ、仕様上固定される値は責務を持つ名前付き定数へ置きます。詳しい判断基準はコーディング規約で管理します。

## 診断と課題選定

準備だけがネットワークと依存更新を使用します。実行は原本を照合し、新しい作業コピーと固定済みの課題用環境で行います。公式スナップショットの内部リンクは到達先を検証して保持し、外部へのリンクと壊れたリンクは拒否します。提出ZIPではリンクを許可しません。

実際のpytestプロセスに観測処理を入れ、読み込んだ対象パッケージとサブモジュールの出所を記録します。Requestsが公開する依存パッケージへの別名は、実際のモジュール名で区別します。コード外の本体を読んだテストを成功と扱いません。import失敗も記録し、元の収集エラーを別の内部エラーへ変えません。

課題選定は未修正・参照パッチだけで行います。候補順と補欠を事前に固定し、成否と除外理由を保存します。選定記録、ケース、JUnit、ソースと依存の証拠を再読込してから使用し、生成結果を見た再選定は行いません。

## 公式接続と環境差

公式Wheelは導入前に期待ハッシュと照合します。開発用subprocessに対してだけ、ソースルートと必要な追加Wheelを設定します。追加依存は課題ごとの仮想環境へオフラインで導入し、ホスト全体へ追加しません。公式の採点関数、テスト、保護対象、成功条件を変更しません。

開発用の補正内容と実際の依存一覧を保存します。正式評価の正確な環境は未確認のため、Private実行を本番環境との完全一致とは扱いません。

## 実行と成果物

ローカルの事前検証で候補ZIPを一度固定します。CPUとGPUで同じZIPと実行コードを使い、実行種別だけを起動引数で渡します。GPU用コードの生成には、完了したCPU記録と制御ケースのハッシュ照合が必要です。

CPUでもモデル・LoRAの宣言と登録、コンパイルを確認します。CUDA確認と推論サーバー起動はGPU評価だけが行います。Notebook全体は監視プロセスの期限で制限し、通常終了・異常終了・期限超過で子プロセス群を停止します。元の失敗を後始末の失敗で隠しません。

公式の課題単位の判定と保存結果を正本とし、欠損・重複・集計不一致・保存エラーを拒否します。分析結果は別の保存先へ出し、取得できない情報を不明として残します。個別テスト通過数や診断ケースを独自の解決数へ換算しません。

候補ZIPは結果内へ保存しますが、正式提出先へ自動出力・送信しません。Kaggleへのアップロードと提出、PR作成と承認・マージはそれぞれ明示的な操作です。
